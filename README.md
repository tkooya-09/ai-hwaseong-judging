# AI화성 챌린지 심사집계표

2026. 9. 17. 시민·공무원 AI 공모전 최종 발표심사를 위한 HTML 심사집계 화면입니다.
HTML만으로 한 PC에서 사용할 수 있고, 동봉한 API와 데이터 저장소를 연결하면 여러 기기의 공동 집계가 가능합니다. 실시간 공동 집계를 사용하려면 Vercel 배포 후 아래 안내에 따라 운영 데이터베이스와 서버 환경변수를 연결해야 합니다.

## 1. HTML을 바로 사용하는 방법

1. `dist/index.html`을 Chrome 또는 Edge에서 엽니다. 별도 설치나 인터넷 연결 없이 점수 입력·집계 기능을 사용할 수 있습니다. 작품 사이트를 열 때는 인터넷 연결이 필요합니다.
2. 처음에는 운영자 화면이 표시됩니다. 왼쪽 ‘입력 담당’에서 심사위원을 선택합니다.
3. 작품을 선택하고, ‘작품 사이트 열기’로 시연을 확인한 다음 5개 항목의 점수를 입력합니다.
4. 점수는 입력을 멈춘 뒤 약 0.65초 후 자동 저장됩니다. ‘저장됨’을 확인합니다. 빈칸은 미입력이며 0점과 다르게 처리합니다.
5. 심사위원 1명당 6개 작품, 총 30개 항목을 입력하고 ‘내 심사 완료 · 제출’을 누릅니다.
6. 다른 심사위원으로 바꿔 같은 과정을 진행합니다. 모두 제출한 뒤 ‘운영자’를 선택합니다.
7. ‘전체 심사 완료 · 결과 집계’를 누르면 시민·공무원 부문별 합계·평균·순위가 표시됩니다.
8. ‘CSV 다운로드’로 결과와 항목별 세부점수를 내려받고, ‘전체 점수 백업’으로 기록을 보관할 수 있습니다.

**단일 PC 모드는 같은 브라우저의 한 탭에서 사용하세요.** 심사위원 선택 기능은 한 PC 입력용이며 접속 인증 기능이 아닙니다. 브라우저 저장소 삭제, 다른 브라우저 사용, HTML 파일 경로 변경 등으로 기존 점수를 읽지 못할 수 있습니다. 결과를 CSV·JSON으로 보관하세요. 여러 기기의 점수가 자동으로 합쳐지지는 않습니다. 업데이트한 파일에서 기존 점수가 보이지 않으면 기존 파일에서 저장한 전체 점수 백업 JSON을 ‘점수 백업 불러오기’로 불러올 수 있습니다. 이 기능은 단일 PC 모드의 운영자 화면에서만 제공하며, 공동 집계 서버의 데이터를 변경하지 않습니다.

## 결과표·서명부 한 장 출력

1. 운영자 화면에서 전체 심사를 완료하고 **최종 집계**로 이동합니다.
2. **결과·서명부 출력 (A4 1장)** 버튼을 누릅니다.
3. 인쇄창에서 **A4 / 가로 / 배율 100% / 머리글 및 바닥글 해제**를 선택합니다. 문서 여백은 10mm로 지정되어 있습니다. 프린터 설정에서 여백을 별도로 크게 지정하면 페이지가 늘어날 수 있습니다.
4. 시민·공무원 결과표 2개와 위원 5명의 자필 서명란이 한 장에 출력됩니다. PDF로 보관하려면 인쇄 대상을 ‘PDF로 저장’으로 선택합니다.
5. 출력 후 **정희석·김규진·홍아름·서호성·정원석** 위원의 서명을 받고 확인일을 적습니다.

표에는 작품명·발표자·위원별 총점·500점 합계·100점 평균·부문별 순위·참고 수상등급이 포함됩니다. 서명란은 자필 서명을 받을 빈 공간이며 전자서명을 대신하지 않습니다. 화면에 현재 저장된 실제 집계결과를 사용하며, 예시 점수를 자동으로 입력하지 않습니다. 출력 버튼은 최신 저장 상태를 다시 확인하여 재심사 중인 결과가 출력되는 것을 차단합니다.

업데이트 방법: 기존 파일에서 **‘전체 점수 백업’으로 JSON을 먼저 저장**한 뒤, 새 HTML을 실행하세요. 기존 점수가 표시되지 않으면 운영자 화면의 **‘점수 백업 불러오기’**로 해당 JSON을 선택합니다. 불러오기는 기존 로컬 데이터를 교체하므로 확인창의 내용을 확인하세요. GitHub/Vercel 사용자는 ZIP 소스를 반영해 다시 배포하면 됩니다. 기존 `EVENT_ID`와 서버 환경변수는 유지합니다.

## 2. GitHub 등록 및 Vercel 배포 준비

### 파일 구성

| 파일 | 용도 |
|---|---|
| `dist/index.html` | 바로 실행 가능한 단일 HTML 완성본 |
| `index.template.html` | HTML 화면·스타일·동작 수정용 원본 |
| `lib/data.json` | 작품 6개, 심사위원 5명, 평가기준 원본 |
| `lib/core.cjs` | 점수 검증·합계·순위·권한·완료 처리 공통 로직 |
| `lib/print.cjs` | 결과표와 5명 서명란의 인쇄 전용 양식 |
| `api/state.js` | Vercel 공동 집계 API |
| `scripts/build.cjs` | 자료와 공통 로직을 단일 HTML로 결합 |
| `scripts/create-codes.cjs` | 운영자·심사위원별 접속 코드 생성 |
| `vercel.json` | Vercel 빌드·배포 설정 |
| `.env.example` | 필요한 서버 환경변수 양식 |
| `tests/` | 점수 로직과 API 검증 |

### 배포 순서

1. ZIP을 풀고 **`package.json`, `api`, `lib`, `dist`가 함께 있는 폴더**의 내용을 GitHub 저장소 최상위에 등록합니다. HTML 한 개만 등록하면 공동 집계 기능은 작동하지 않습니다. `.env` 등 실제 비밀키 파일은 올리지 않습니다.
2. Vercel에서 해당 GitHub 저장소를 가져옵니다. Framework Preset은 `Other`, Build Command는 `npm run build`, Output Directory는 `dist`입니다. `vercel.json`에 설정되어 있습니다. Node.js는 지원되는 22 이상 버전을 선택합니다.
3. Vercel Marketplace에서 **Upstash Redis** 저장소를 프로젝트에 연결합니다. 별도 이용 계정과 저장소 설정이 필요합니다.
4. 다음 서버 환경변수를 프로젝트에 등록합니다. Production과 Preview는 서로 다른 `EVENT_ID`를 사용하여 연습 데이터와 행사 데이터를 분리하세요.

| 환경변수 | 값 |
|---|---|
| `UPSTASH_REDIS_REST_URL` | Upstash Redis REST API 주소 |
| `UPSTASH_REDIS_REST_TOKEN` | Upstash Redis 쓰기 가능한 REST API 토큰 |
| `ADMIN_TOKEN` | 운영자 전용 접속 코드, 24자 이상 |
| `JUDGE_TOKENS` | 심사위원 접속 코드 5개를 담은 JSON 객체 |
| `EVENT_ID` | 행사별 저장공간 구분값. 예: `hwaseong-2026-final` |

자동 주입되는 변수명이 `KV_REST_API_URL`, `KV_REST_API_TOKEN`인 경우에도 API가 인식합니다. 읽기 전용 토큰은 점수 저장에 사용할 수 없습니다.

5. Node.js가 설치된 컴퓨터에서 아래 명령으로 서로 다른 접속 코드 6개를 생성합니다. 출력되는 `ADMIN_TOKEN`, `JUDGE_TOKENS` 값을 각각 Vercel 환경변수에 복사합니다. 접속 코드는 HTML이나 GitHub 파일에 넣지 않습니다.

```bash
node scripts/create-codes.cjs
```

`JUDGE_TOKENS`는 아래 구조입니다. 예시 문자열을 그대로 사용하면 안 됩니다. 값은 각각 24자 이상이고 모두 달라야 합니다.

```json
{"j1":"정희석_심사위원_코드","j2":"김규진_심사위원_코드","j3":"홍아름_심사위원_코드","j4":"서호성_심사위원_코드","j5":"정원석_심사위원_코드"}
```

6. 환경변수를 등록한 뒤 배포하거나 다시 배포합니다. 환경변수 이름과 값은 서버에서만 사용합니다.
7. 배포 URL을 열고 운영자 코드로 접속합니다. 각 심사위원은 **같은 URL과 자신의 코드**로 접속합니다. 코드로 역할이 결정되어 다른 위원 점수를 수정할 수 없습니다.
8. 상단에 **‘공동 집계 연결 · 3초 자동 갱신’**이 나타나면 연결된 상태입니다. 다른 기기 입력은 약 3초 간격으로 조회됩니다. 실제 갱신 시간은 네트워크·서버 응답시간과 브라우저 탭 활성 상태에 영향을 받습니다.
9. 행사 전 별도 `EVENT_ID`에서 기기별 저장·제출·완료·CSV 다운로드를 확인한 뒤 행사 데이터 공간으로 전환합니다. 연습 점수는 단일 PC 모드에서 공동 집계로 자동 이전되지 않습니다.

**GitHub Pages에 HTML만 올리는 경우:** 정적 화면은 표시되지만 `/api/state`가 실행되지 않습니다. 여러 기기의 공동 집계에는 동봉한 서버 코드가 실행되는 Vercel 배포와 Redis 연결이 필요합니다.

## 3. 심사 기준과 계산 방식

| 항목 | 배점 | 기준 |
|---|---:|---|
| 창의성 | 20 | 내용의 독창성 및 동일·유사 사례 여부 |
| 효율성 | 20 | 비용·인력 등 투입 대비 결과와 행정혁신 효과 |
| 적용범위 | 20 | 실제 적용 가능한 대상 및 수혜 대상의 범위 |
| 계속성 | 20 | AI 활용의 점진적 확대를 위한 연차별 준비사항 |
| 기술성 | 20 | 핵심 기술의 실질적 구현 정도 및 출품작의 완성도 |
| 합계 | 100 | 심사위원 1명 기준 |

- 항목별 0~20점 정수 입력입니다. 음수, 20점 초과, 소수는 차단합니다.
- 5명 점수를 모두 합산하여 작품별 500점 만점으로 계산합니다. 평균은 합계 ÷ 5, 100점 만점으로 소수 둘째 자리까지 표시합니다.
- 최고·최저점 제외, 가점, 항목별 추가 가중치는 적용하지 않습니다.
- 시민 3작품과 공무원 3작품을 각각 집계합니다. 6개 작품을 섞어 통합순위를 매기지 않습니다.
- 동점이면 공동순위로 표시합니다. 예를 들어 1위가 2작품이면 `1·1·3`입니다. 동점 작품의 수상등급은 ‘협의 필요’로 표시합니다.
- 점수 순위에 따른 대상·최우수상·우수상은 참고 표시입니다. 시상등급·인원 변경 등 최종 결정은 이 버전에서 자동 처리하지 않습니다.

## 4. 역할과 운영 절차

| 기능 | 심사위원 | 운영자 |
|---|---|---|
| 작품 소개·시연 사이트 열기 | 가능 | 가능 |
| 점수 입력 | 본인 점수만 | 공동 집계 모드에서는 불가 |
| 다른 위원의 항목별 점수 조회 | 불가 | 가능(API·백업), 화면은 현황 중심 |
| 심사표 제출 | 본인 심사표 | 불가 |
| 제출 완료 상태 확인 | 가능 | 가능 |
| 전체 완료·순위·CSV 출력 | 불가 | 가능 |
| 제출한 심사표 수정 허용 | 불가 | 사유 입력 후 가능 |

운영자는 ‘심사 현황’에서 제출 완료 위원의 ‘수정 허용’을 누르고 사유를 기록할 수 있습니다. 해당 심사표의 제출과 전체 집계 완료 상태가 해제됩니다. 위원이 점수를 수정해 다시 제출하면 운영자가 전체 완료를 다시 진행합니다. 변경 사유·시간·역할·버전은 전체 백업의 `audit`에 남습니다. 점수 입력 기록은 작업 이력이며, 모든 과거 점수 값의 버전 보관 기능은 아닙니다.

연결이 끊기면 화면에 실패가 표시되고 미저장 입력은 현재 열린 화면에서 유지됩니다. ‘지금 저장’으로 재시도할 수 있습니다. 저장에 실패한 상태에서 창을 닫기 전 ‘내 입력 백업’으로 내용을 저장하세요. 공동 집계 모드의 미저장 초안은 새로고침·창 닫기 후 자동 복구되지 않습니다.

같은 위원 코드로 여러 창에서 동시에 수정하면 버전 충돌을 감지합니다. ‘내 입력 백업’으로 기록을 남기고 ‘최신 점수 불러오기’를 누른 뒤 필요한 점수만 다시 입력합니다. 서로 다른 위원의 동시 저장은 Redis 비교·교환으로 병합되어 다른 위원 점수를 덮어쓰지 않습니다.

## 5. 반영 자료

- `2026년 공모전 발표심사 준비계획_v2.hwpx`: 참고1 평가기준·심사위원, 참고2 제안 현황·발표 순서.
- `시민, 공무원 심사표.xlsx`: 작품 설명과 작품 URL.
- 준비계획 첫 부분의 ‘2026.9.17.(화)’는 같은 문서 참고1의 ‘2026.9.17.(목)’와 맞춰 목요일로 반영했습니다.
- 준비계획 참고3 연락처 표는 시민·공무원 구분이 다른 표와 상충하여, 참고2와 엑셀의 일치하는 구분을 적용했습니다.
- 연락처·이메일은 HTML과 배포 자료에 포함하지 않았습니다. 실제 링크의 가동 여부는 확인하지 않았으며 첨부자료의 URL을 그대로 연결했습니다.

## 6. 수정 및 검증

작품·심사위원 표시를 수정하려면 `lib/data.json`, 화면을 수정하려면 `index.template.html`을 편집하고 다음 명령을 실행합니다. 출력된 `dist/index.html`은 다른 파일 없이 단독 실행됩니다. `dist/index.html`만 수정하면 다음 빌드 때 덮어써지므로 수정용 원본을 편집하세요.

```bash
npm run build
npm test
```
